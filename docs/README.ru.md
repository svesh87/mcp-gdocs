# mcp-gdocs

MCP-сервер для Google Slides, Sheets, Docs и Drive, который работает от имени одного
вошедшего человека и правит презентации так, как это делает сам редактор.

Ради презентаций всё и затевалось. Универсальный гугловый сервер правит колоду тем, что
двигает текстовые блоки по выдуманным координатам, пишет символы маркеров в обычный текст
и вместо настоящей таблицы кладёт россыпь фигур. Получается то, что выглядит сломанным у
всех, кто это открыл, и чинится только переделкой слайда. Здешние инструменты работают
вместе с шаблоном, а не в обход него: родные вложенные списки, стили, снятые с собственных
слайдов колоды, настоящие таблицы и миниатюра, чтобы проверить результат.

## Почему узкие инструменты по слайдам работают

Каждый пункт — решение, а не деталь реализации:

- **Родные списки, а не нарисованные руками.** `gdocs_slides_replace_body_nested_list`
  отправляет текст с табуляциями для глубины и просит Slides сделать из него список.
  Дальше Google сам считает отступы, маркеры и интервалы по шаблону. Сервер, который
  расставляет маркеры сам, попадает почти точно, а это хуже, чем мимо.
- **Стиль копируется, а не выдумывается.** `gdocs_slides_copy_title_style` читает первый
  ран настоящего заголовка и переносит эти поля. Никто не гадает, какой тут «шрифт
  заголовков».
- **Сначала посмотреть.** `gdocs_slides_inspect_text_structure` показывает, что лежит в
  текстовом блоке — абзацы, маркеры, вложенность, — до того как это заменят.
- **Таблица должна быть таблицей.** `gdocs_slides_create_table_with_text` создаёт
  настоящую таблицу слайдов с ширинами колонок, шрифтами и выравниванием по колонкам.
  Ряды текстовых блоков похожи на таблицу ровно до первой правки.
- **Проверять глазами.** `gdocs_slides_export_thumbnail` отрисовывает слайд, чтобы агент
  посмотрел на сделанное, а не поверил отправленному батчу.
- **Никаких произвольных батчей.** Инструмента, который передаёт в
  `presentations.batchUpdate` запросы вызывающего, здесь нет. Именно он и делает колоды
  кривыми.

Подход взят с рабочего сервера, который коллега написал ровно под эту задачу; здесь то же
поведение на Go и остальные гугловые редакторы вокруг.

## Удаление кончается на корзине

Внутри презентации, документа или книги удаление — обычная правка: скопированная колода
сводится к нужным слайдам, а неудачный шаг оставляет за собой лишний абзац или таблицу,
которые кто-то должен уметь убрать. Сам файл уходит не дальше корзины, откуда владелец
достаёт его тридцать дней. Очистки корзины, безвозвратного удаления файла, удаления папки
и диска здесь нет вовсе — это проверяет тест, и не только по именам инструментов, но и по
методам клиента.

По умолчанию не включено ничего из этого. Каждый удаляющий инструмент живёт в своей
группе — `slides-delete`, `docs-delete`, `sheets-delete`, `drive-delete`, — и кому нужно,
тот называет её: `--tools=all,docs-delete`. Так же устроена раздача доступа: она
единственная делает файл видимым снаружи аккаунта и живёт в `drive-share`.

Всё, что вообще что-то меняет, требует `--allow-write`. Без него сервер отдаёт только
читающие инструменты.

## Набор инструментов

Сто тридцать семь описаний в контексте агента — это сто тридцать, которые он никогда не
позовёт. `--tools` выбирает, что сервер отдаёт, по семейству и по тому, что инструменты
делают:

```
--tools=slides-read,docs-read     # ровно эти две группы
--tools=docs                      # семейство: чтение и запись, без удаления
--tools=all,sheets-delete         # всё обычное плюс один вид удаления
GDOCS_TOOLS=drive-read            # то же через окружение, для compose
```

Группы — `slides-`, `sheets-`, `docs-` и `drive-`, у каждой `read`, `write` и `delete`,
плюс `drive-share`. Имя семейства значит его читающую и пишущую половины; `all` — всё,
кроме удаления и раздачи доступа. Неизвестное имя — отказ при старте со списком известных.
Если не задавать вовсе, набор такой же, каким был всегда: всё, кроме удаления и раздачи.

По HTTP тот же процесс отдаёт ещё и по пути на семейство, чтобы проект подключал только
нужное:

```
/mcp          весь набор
/mcp/slides   /mcp/sheets   /mcp/docs   /mcp/drive
```

Это окна в один сервер — тот же вход, тот же токен, то же хранилище, — и окно не может
показать того, чего не разрешил `--tools`.

## Инструменты

Их сто тридцать семь: покрыт каждый запрос трёх API, кроме пяти, которые ходят в BigQuery.
Сервер, поднятый без `--allow-write`, регистрирует только читающие, а четыре, которые
трогают диск — `gdocs_drive_export_file`, `gdocs_drive_download_file`,
`gdocs_drive_import_file` и `gdocs_slides_export_images`, — появляются только тогда, когда
`--files-dir` называет каталог, которым им можно пользоваться.

## Доступ

Сервер работает от имени одного человека — того, кто прошёл вход. Сервис-аккаунта и
domain-wide delegation нет сознательно: ключ сервис-аккаунта с делегированием умеет
олицетворять любого сотрудника без его ведома, и образ с таким ключом — компрометация всей
компании, ждущая утечки. Настройка Google Workspace по полям и обоснования —
в [docs/SETUP.ru.md](SETUP.ru.md).

Два секрета, и они разделены:

- **OAuth-клиент** — это приложение. Либо файл, который скачивает Google Cloud Console,
  путь к нему в `--credentials`, либо две его половины в переменных
  `GOOGLE_OAUTH_CLIENT_ID` и `GOOGLE_OAUTH_CLIENT_SECRET` — именно это отдаёт хранилище
  паролей, и тогда о приложении на диске нет вообще ничего. Если заданы оба способа,
  побеждает окружение: оставшийся от прежней настройки файл не должен незаметно
  перевешивать то, что только что подсунули.
- **Токен** — это консент одного человека. Появляется при его собственном входе и остаётся
  файлом с правами 0600 в каталоге из `--token-dir`. Файлом, а не переменной, потому что
  сервер перезаписывает его при каждом обновлении access-токена, а хранилище секретов — не
  то место, куда процесс пишет сам.

Ни то, ни другое не коммитится и не собирается в образ: оба в `.gitignore` и
`.dockerignore`.

## Вход

На машине с браузером:

```bash
mcp-gdocs login --credentials ./gcp-oauth.keys.json --token-dir ./tokens
```

Команда печатает адрес, ждёт на loopback-порту возвращения браузера и пишет токен.

В контейнере браузера нет, поэтому вход идёт через страницу, которую сервер отдаёт сам.
Опубликуйте его порт на loopback и откройте:

```
http://127.0.0.1:8819/login?key=<MCP_AUTH_TOKEN этого сервера>
```

Страница говорит, входил ли кто-нибудь и что будет запрошено, а одна кнопка отправляет
браузер на экран согласия Google. Google возвращает его на `127.0.0.1` на тот же порт —
такой адрес гугловый клиент типа Desktop принимает без регистрации чего-либо в консоли, —
и по дороге назад пишется токен.

Ключ в адресе, потому что браузер не шлёт заголовок `Authorization` сам по себе; поэтому
страница отдаётся с `no-store` и `no-referrer`, а переход к Google — отправка формы, а не
ссылка: пересланный адрес `/login` покажет страницу, а не экран согласия.

Если сервер на другой машине — не выставляйте порт наружу, а пробросьте его: Google
возвращает только на loopback. `ssh -L 8819:127.0.0.1:8819 <хост>`.

## Запуск

```bash
mcp-gdocs --credentials /config/gcp-oauth.keys.json --token-dir /config/tokens --allow-write
```

| Флаг | Что делает |
|---|---|
| `--transport` | `stdio` (по умолчанию) или `streamable-http` |
| `--address` | адрес прослушивания для `streamable-http`, по умолчанию `127.0.0.1:8819` |
| `--credentials` | путь к файлу OAuth-клиента. Обязателен, если клиент не приходит из окружения |
| `--token-dir` | каталог, где живёт токен. Обязателен |
| `--scopes` | какие права запрашивать, через запятую. Пусто — значит `drive`, `spreadsheets`, `presentations`, `documents` |
| `--allow-write` | зарегистрировать инструменты, которые меняют документы. По умолчанию выключено |
| `--version` | напечатать версию и выйти |

Три переменные окружения — потому что секрет во флаге виден в списке процессов:

| Переменная | Что это |
|---|---|
| `MCP_AUTH_TOKEN` | bearer-токен, которого требует HTTP-транспорт. Без него сервер не стартует на `streamable-http`: всё, что дотянулось до этого порта, действует от имени вошедшего человека |
| `GOOGLE_OAUTH_CLIENT_ID` | OAuth-клиент вместо `--credentials`. Обе половины или ни одной |
| `GOOGLE_OAUTH_CLIENT_SECRET` | вторая половина |

Полный скоуп `drive`, а не `drive.file`, — сознательно: колода делается копированием
шаблона, а `drive.file` видит только файлы, созданные самим приложением, и потому шаблон
не откроет вовсе.

В контейнере — клиент подсовывается переменными, монтируется только токен:

```bash
docker run --rm -i --user "$(id -u):$(id -g)" \
  -e GOOGLE_OAUTH_CLIENT_ID -e GOOGLE_OAUTH_CLIENT_SECRET \
  -v "$HOME/.local/share/mcp-gdocs:/tokens" \
  ghcr.io/svesh87/mcp-gdocs:latest \
  --token-dir /tokens --allow-write
```

Образ собран `FROM scratch` и работает от 65532, поэтому тот, кто монтирует каталог
токенов, переопределяет пользователя своим идентификатором: иначе каталог не записываем и
сервер выходит, прямо об этом сказав.

## Навыки

По одному на редактор, потому что колода и книга портятся по-разному:

- [`skills/gdocs-slides/`](../skills/gdocs-slides/SKILL.md) — сборка колоды: порядок
  вызовов, что прочитать перед правкой и почему блоки никогда не двигают руками.
- [`skills/gdocs-sheets/`](../skills/gdocs-sheets/SKILL.md) — сборка книги: почему
  форматирование — это разложение на прямоугольники, а не заливка, и почему размер и
  локаль решаются при создании.

У каждого рядом два справочника — способ работы и факты об API стареют по-разному:
`references/controls.md` перечисляет все ручки по тому, что они меняют (чем читается, чем
пишется, в каких единицах), а `references/pitfalls.md` — ловушки, у каждой сказано, как она
выглядит в документе и чем лечится, а в конце то, чего API не сообщает вовсе.

## Разработка

```bash
gofmt -l .
go vet ./...
go test ./... -coverprofile=coverage.out
go tool cover -func=coverage.out | tail -1     # не ниже 80%
docker build -t mcp-gdocs:dev .
```

В тестах лежат **golden-файлы на тела запросов**: точный JSON, который сервер отправляет в
Slides, Sheets и Docs, — `internal/tools/testdata/`. В них весь смысл набора тестов, потому
что вид колоды решают именно эти тела, а не то, какие методы вызвались.
`go test ./... -update` их перезаписывает, и такая перезапись уместна в коммите, который
говорит, что изменилось в результате.
